# 多笔记关系归纳与分歧 prompt

这份 prompt 解决一个具体问题：**你读完一批笔记后，想知道"它们之间到底在说什么"**——不是逐篇复述，而是回答：

- 它们在哪些问题上达成共识？
- 它们在哪些点上真正分歧？
- 方法上分裂还是理论上分裂？
- 还有什么 gap 没被这一组笔记覆盖？
- 这组笔记能不能聚成一个 argument block？

这是从"读完了"到"能写"之间的关键一步——经验上很多人在这里卡住，因为同时打开 8 篇 reading note 让大脑过载。把这一步外包给 LLM 是合理的；但 LLM 容易写成"X 说...Y 说...Z 说..."的流水账，这份 prompt 的护栏就是为了防这个。

## 复制给 LLM 的 prompt

```text
请帮我把下面这 N 篇 reading notes 整理成"问题空间式"关系归纳。

## 任务边界

你只负责：
- 跨笔记找共同关切 / 关键分歧 / 方法分裂 / 理论分裂
- 指出剩余 gap
- 给出 Argument Block 候选（不替我命名最终版）

你不要：
- 不要逐篇复述每篇笔记说了什么——那是文献列表不是归纳
- 不要去外网补这些文献"本来应该说什么"——只依据眼前的 reading note
- 不要直接起草 argument block 段落——那是后续动作，需要我确认
- 不要给找到的分歧加情绪化判断（"X 的立场更合理"）——除非我问

## 输入

### 我关心的问题空间 / 主题
[一句话，例如："VLM 输出在人文研究中应该被当成解释还是中间证据？"或"abductive analysis 在 mixed methods 中的角色"]

### 可选：已知的 working hypothesis 或导师反馈
[一句话，引导归纳方向；如无可留空]

### Reading notes（4-10 篇）

[贴每篇 reading note 的完整正文或文件路径。建议格式：]

---
笔记 1: [[文件名]]
[正文或文件路径]
---
笔记 2: [[文件名]]
[正文或文件路径]
---
...

## 归纳要求

按以下结构输出，不要逐篇罗列：

### A. 共同关切 / Shared Concerns

这些笔记共同围绕哪些问题？（不是"都引用了某文献"，而是"都试图回答某个问题"）

- 共同关切 1: ...
  - 体现在 [[笔记1]], [[笔记3]], [[笔记5]] —— 但每篇切入点略有不同：
    - [[笔记1]] 从 [方面1] 切入
    - [[笔记3]] 从 [方面2] 切入
    - [[笔记5]] 从 [方面3] 切入
- 共同关切 2: ...

### B. 关键分歧 / Key Disagreements

注意：分歧必须具体——不能只说"两位作者立场不同"，要说"在 X 问题上，[[笔记A]] p.12 说 ABC，[[笔记B]] p.34 说 CBA"。

- 分歧 1: [问题]
  - [[笔记A]] 立场: ...（出处 + 引文）
  - [[笔记B]] 立场: ...（出处 + 引文）
  - 这个分歧是否可调和？: [可调和 / 不可调和 / 取决于 X]
- 分歧 2: ...

### C. 方法分裂 / Methodological Split

如果这组笔记在方法层面有不同路径，列出：

- 方法路径 1: [...] — [[笔记]]
- 方法路径 2: [...] — [[笔记]]
- 谁能桥接、谁不能桥接？

如果没有方法分裂，直接写: "这组笔记在方法层面没有显著分裂；它们的差异在 [理论 / 案例 / 时段]。"

### D. 理论分裂 / Theoretical Split

如果这组笔记基于不同的理论框架（如 critical theory vs pragmatism vs empiricism），列出：

- 理论框架 1: [...] — [[笔记]]
- 理论框架 2: [...] — [[笔记]]
- 这些框架是否互斥？

如果没有理论分裂，直接写: "这组笔记共享同一理论框架（约 [一句话描述]），分裂主要在 [其他维度]。"

### E. 剩余 Gap / What Gap Remains

这一组笔记覆盖了你关心的问题空间的哪些部分，没覆盖哪些部分？

- 已覆盖: [...]
- 部分覆盖（薄）: [...]
- 完全没覆盖: [...] —— 建议下一步检索关键词: [...]

### F. Argument Block 候选

这组笔记能不能成为一个 argument block？给我候选判断（不要替我定稿）：

- **候选 block 名**: [一个工作命名，明确说"这是工作命名，可能改"]
- **问题空间**: [一句话]
- **核心 reading notes**: [[笔记A]], [[笔记C]], [[笔记E]]（哪些是核心证据）
- **支持 reading notes**: [[笔记B]], [[笔记D]]（哪些是相邻支撑）
- **该 block 的论证结构（草图）**:
  - 共识起点: ...
  - 分歧节点: ...
  - 我的可能位置: [TODO: 用户决定]
- **该 block 成立的条件**: 
  - 需要再读 [...] 才能确认
  - 或：已可成立，可以进入 03_Argument_Blocks 起草

如果不能成 block，直接写: "这组笔记适合留在 reading note 层级，理由: [...]。"

## 不确定标记规则

每个归纳判断要标明确定度：

- `[确定]` — 这个判断直接来自某篇笔记的明确陈述
- `[初步推断]` — 这是基于多篇笔记综合的解读，可能有偏差
- `[需用户确认]` — 几篇笔记证据相互冲突，无法确定该归哪边
- `[笔记内容不足]` — 第 N 篇笔记内容太薄，无法可靠归纳

## 边界

- 不替我命名最终的 argument block / concept / method
- 不去外网核证笔记里的引文（那是 04 / 07 的事）
- 不"和稀泥"——分歧就是分歧，不要写"两位作者都有道理"
- 不归纳超出输入笔记范围的内容——除非我问"我还应该读什么"
- 如果归纳过程中发现某篇笔记被严重误读（比如 frontmatter 里 relevance 与正文判断矛盾），单独提出来

## 停下点

归纳完成后停下，问我：
"归纳完成。下一步可选：
(a) 选定一个候选 block 进入起草（去 写作/）
(b) 先补 [...] 文献再回来重做（去 02 / 06）  
(c) 选某条分歧做压力测试（去 审阅/07_论点压力测试）
(d) 就停在这里，把报告归档"
等我回复再继续。
```

## 用 08 + 09 串联

最常见的工作流：

```text
我想看我读过的笔记里关于 [话题 X] 都说了什么
   ↓ 08_笔记内检索_prompt.md
   ↓ 找到 6 篇相关笔记
我想知道它们之间的分歧
   ↓ 09_多笔记关系归纳与分歧_prompt.md（本 prompt）
   ↓ 输出问题空间式归纳 + Argument Block 候选
我决定升级成 argument block
   ↓ 写作/（如果有起草 argument block 的 prompt）
```

或者你已经手挑了一组笔记（不需要 08），直接进 09。

## 与"逐篇文献综述"的区别

很多人会问 LLM："给我写一段文献综述讲讲 X 话题。" 结果拿到的是 "Smith (2024) argues that... Jones (2023) suggests... Brown (2022) shows..." 这种逐篇点名式段落——这就是综述拖延症的来源，因为它没真的整理出分歧和 gap。

本 prompt 强制不允许这种输出：必须以"问题空间"组织，且分歧必须具体到出处。如果 LLM 输出仍然像流水账，让它**重新做**——不要接受。

## 与 evil-thesis 现有 prompt 的区别

| Prompt | 输入 | 输出 | 何时用 |
|---|---|---|---|
| `04_单篇reading_note_*` | 一篇 PDF | 一篇 reading note | 你在读单篇 |
| `07_批次整理_Codex_*` | 一批 reading reports | metadata / link / index 更新 | 你已读完一批，要整理库结构 |
| `08_笔记内检索_*` | 关键词 + 目录 | 命中笔记列表 | 你想"我读过哪些笔记讨论 X" |
| **`09_多笔记关系归纳与分歧`（本）** | **4-10 篇 reading notes** | **问题空间式归纳 + block 候选** | **你想"它们之间到底在说什么"** |

09 是从"读完了"到"能写"之间的桥；07 是从"读完了"到"库整齐"之间的桥。两件事都做，但目的不同——不要混。
