# 关键词检索、下载、评分、阅读 prompt

> 我还没有指定某一篇论文，只给一个关键词、主题或问题。LLM 需要先搜索相关文献，下载可获取的 PDF，给候选文献评分，然后等我确认，再读最相关的文献。

## 复制给 LLM 的 prompt

```text
请按照我的关键词检索阅读流程执行。

## 任务目标

我会给你一个关键词、主题或研究问题。你需要：

1. 根据关键词搜索相关文献；
2. 优先通过可用 API / 学术搜索工具找最近 5-8 年的重要文献，
   同时不要遗漏经典文献；
3. 判断哪些文献真正适合我的论文；
4. 下载或定位可获取的 PDF；
5. 给我一张候选文献评分表；
6. 停下来等我确认；
7. 我确认后，再逐篇阅读最相关的文献，并生成正式 reading note。

## 阶段一：理解关键词和搜索范围

请先把我的关键词拆成几组搜索方向：

- 理论关键词；
- 方法关键词；
- 材料/领域关键词；
- 相邻领域关键词；
- 可能需要排除的无关方向。

输出：

## 搜索方向

| 方向 | 关键词组合 | 为什么要搜 |
|---|---|---|
| 理论 | ... | ... |
| 方法 | ... | ... |
| 材料/领域 | ... | ... |

## 阶段二：搜索文献

请使用可用工具搜索文献。优先级：

1. 如果有可用 API，优先使用 Semantic Scholar / OpenAlex / Crossref 等工具；
2. 已知标题或 DOI：直接精确搜索；
3. 探索主题：用关键词组合搜索；
4. 检查是否有开放获取 PDF；
5. 检查本地 Zotero（如有）是否已有；
6. 只下载开放获取 PDF，不使用非法来源。

搜索后必须做存在性核验：每一篇候选在进入评分表前，必须在
Semantic Scholar / OpenAlex / Crossref 至少一个库里核到（标题 + 作者 + 年份匹配）。
核不到的，标注 [未核实，可能不存在]，不要凭印象或记忆把文献写进表里。

如果需要下载 PDF：
- 优先保存到用户指定路径；
- 如果没有指定，说明建议路径；
- 如果无法下载，标注"需用户手动获取"；
- 不要因为下载失败就放弃候选文献；保留在候选表里，标注获取状态。

## 阶段三：候选文献评分表

请给我 8-15 篇候选文献，按相关度排序。

## 候选文献评分表

| 排名 | 作者/年 | 标题 | 类型 | 来源·核验 | 相关度 | 获取状态 | 为什么相关 | 建议 |
|---|---|---|---|---|---|---|---|---|
| 1 | ... | ... | 理论/方法/案例/综述 | 期刊(peer-reviewed)·已核 | 5★ | PDF 已获取 / Zotero 已有 / 需手动获取 | ... | 精读 |

「来源·核验」列说明：
- 来源类型：期刊(peer-reviewed) / preprint / 专著或编著章节 / 报告 / 会议 / 灰色文献 / 疑似 predatory；
- 核验状态：已核 / [未核实，可能不存在]。

评分规则（相关度只评"与我的论证多相关"，与来源质量分开看）：
- 5★：直接支撑我的核心论证，建议精读；
- 4★：高度相关，可进入文献综述或方法论；
- 3★：有用但距离较远，可轻读或背景引用；
- 2★：相关性弱，暂不读；
- 1★：基本不相关。

## 阶段四：停下来等我确认

候选表输出后必须停下，问我：
"你想先读哪几篇？是否按评分从高到低开始？"

不要自动开始阅读。

## 阶段五：确认后逐篇阅读

我确认后，每次只读一篇。

阅读时使用 01_直接阅读已下载文献_prompt 的模板。

每篇读完后输出：

## 本次阅读报告

completed: [[文件名]]
dialogue: [[相关文献A]], [[相关文献B]]
unsure:

## 后续升级建议

candidate_type: stay / argument / concept / method / core_source / background
confidence: low / medium / high
reason:

然后停下，等我说"继续"再读下一篇。

## 输入

关键词 / 主题 / 问题：
[在这里填]

希望最多候选数量：
[例如 10 篇]

希望优先阅读数量：
[例如 3 篇]
```
